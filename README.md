# Easy Discovery

OpenWrt / ImmortalWrt 的 LuCI 局域网设备与无线 ADB 发现应用。软件包名称为 `luci-app-easy-discovery`，安装后从 **服务 → Easy Discovery** 进入。

本项目从 EasyADB 中的 `luci-app-avahi-web` 独立演进，保留旧客户端的 ADB 扫描入口，在同一页面聚合设备信息、依赖安装、服务管理和受限客户端授权。

## 页面与功能

页面按已确认的 [HTML 原型](docs/ui-preview.html) 实现，外层使用路由器原有 LuCI 导航。

| 页面 | 内容 |
| --- | --- |
| 设备发现 | 设备名称、主机名、IPv4/IPv6、MAC、网络、型号/厂商及信息来源；搜索、筛选、分页和详情抽屉 |
| ADB 发现 | Avahi/D-Bus 就绪状态、无线 ADB 端点、搜索与协议筛选、端点复制及设备关联 |
| 运行环境 | 分开的「依赖安装」与「服务管理」；安装计划、后台任务输出、启动/停止/重启、开机自启及可选 ARP 增强 |
| 接口授权 | 独立 `easyadb` 账号、四项发现能力、一次性密钥、权限修改、密钥轮换、撤销及 API 示例 |

### 设备信息从哪里来

- 基础聚合：DHCP 租约、LuCI 主机提示、IPv4/IPv6 邻居表。
- Avahi 可用时：读取允许网络中的 mDNS 服务，补充主机名及设备明确上报的型号、厂商字段。
- 可选 ARP：安装 `arp-scan` 后由管理员单独开启，在明确发起发现时探测有限的本地 IPv4 网段。
- 同一个网络内按 MAC 聚合多地址；无 MAC 时保留基于地址的临时身份。不会按设备名称跨网络合并。

这是路由器当前可观测设备的聚合。休眠设备、静态地址设备、隔离客户端和不发布服务的设备可能不出现；型号没有可靠来源时显示“未识别”，不会根据 IP 或主机名猜测。

设备状态区分近期可达证据、有效租约与缓存。租约和邻居缓存不等于实时在线；`last_seen` 只有邻居 `REACHABLE` 或 ARP 响应等明确证据才会更新。

### 发现与列表的边界

`list` 只读快照，`scan` 才发起一次采集；应用没有后台定时扫描。网页中的安装进度只在任务活动期间查询。

快照位于 `/tmp/easy-discovery/discovery`，重启后清空。设备快照最多 256 条，每种地址最多 8 个；未重新观测到的历史记录最多保留 24 小时。ADB 最多 32 个端点，同一设备可有多个地址或端点，因此端点数不等于物理设备数。

## 首次使用

1. 按 [构建与安装说明](docs/BUILD.md) 获取与固件对应的安装包并安装。
2. 打开 **服务 → Easy Discovery → 设备发现**，点击发起发现。基础聚合不要求安装 Avahi。
3. 需要无线 ADB 或 mDNS 信息时，在 **运行环境 → 依赖安装** 安装 D-Bus 与 Avahi，再到 **服务管理** 启动它们。启动 Avahi 会先确认并启动 D-Bus。
4. 根据需要单独设置开机自启。安装完成不代表服务已经运行，页面始终回读实际状态。
5. 若需要外部程序读取结果，在 **接口授权** 创建专用账号，明确选择权限并保存本次显示的密钥。

安装依赖时使用当前软件源索引；软件源未初始化或索引过期时，先在路由器的系统软件包页面更新索引。应用不会批量升级系统软件包。

## 网络范围

默认只使用逻辑网络 `lan`。配置位于 `/etc/config/easy-discovery`：

```uci
config discovery 'settings'
    list network 'lan'
    option arp_scan '0'
```

需要同时发现访客网时，可由管理员追加对应的逻辑网络，例如 `list network 'guest'`。网络必须实际启用并有可用的本地接口。常见的 `wan` / `wan6` 逻辑网络会被排除；不要将外网接口加入配置。

ARP 增强默认关闭，只处理最多两个 `/24` 至 `/30` 的本地 IPv4 网段，其他范围仍使用基础信息。设置只影响下一次显式扫描。

## 对外接口与授权

两个 RPCD 对象分别提供 `list` 与 `scan`：

| 对象 | `list` | `scan` |
| --- | --- | --- |
| `easy-discovery.devices` | 设备发现快照 | 采集设备信息 |
| `easy-discovery.adb` | ADB 端点快照 | 发现无线 ADB 服务 |

客户端先登录 RPCD，再携带会话调用。四个方法有独立 ACL，外部账号不能安装软件、控制服务或管理授权。两种发现接口沿用原随机密钥、SHA-512-crypt、RPCD 会话及 ACL 策略；传输加密使用 HTTPS。

轮换、修改权限或撤销时，只清理专用账号的会话。清理失败会保留暂停状态，页面提供轮换恢复或撤销入口；不会将旧权限仍有效的操作报告为成功。

- [授权、迁移及异常恢复细节](docs/AUTHENTICATION.md)

## 从 luci-app-avahi-web 迁移

新旧软件包拥有同名兼容文件，声明互斥，不能同时安装。迁移前备份路由器配置，先卸载旧 `luci-app-avahi-web`，再安装新包。

新应用不自动改写 `/etc/config/rpcd` 中的旧 `rpcd.easyadb` 账号、密码哈希或权限。原客户端仍可使用原凭据调用：

```text
file.exec /usr/libexec/luci-avahi-scan scan
```

旧角色 `luci-avahi-easyadb` 仍只允许这个固定命令。旧账号要使用新列表接口，需要管理员在接口授权页面明确授予对应能力；仅轮换密钥不会扩权。ADB 的发现仍是端点发现，不会自动连接、配对设备或执行 ADB 控制命令。

## 开发与验证

当前版本为 `0.1.0`，软件包修订号 `2`。代码包含发现后端、RPCD ACL、LuCI 四页界面、运行测试和 APK 构建工作流。测试包含真实 ucode 格式化、隔离授权/环境事务及 DOM 页面交互；具体结果与模拟边界见 [验证说明](docs/VERIFICATION.md)。

**测试与 APK 构建** 工作流可在 Actions 页面手动运行，也会在 `ci/**` 分支推送时运行。默认构建平台为已确认的 `qualcommax/ipq60xx`，每轮解析官方 ImmortalWrt SNAPSHOT SDK、校验下载并保存版本记录。普通 `main` 提交不会自行派发测试或构建，便于按调试模式决定何时执行。

Git 提交标题与正文使用中文。用户明确指定“改 BUG 模式”或“调试模式”时，不运行测试、构建、lint 或 CI；正常开发只做与改动风险相关的检查。
